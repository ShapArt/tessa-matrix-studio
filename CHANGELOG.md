# Changelog

## 1.10.3 — 2026-09-04

- Исправлена каскадная локализация дублей: если пропуск одной конфликтующей Excel-строки возвращает исходную строку TESSA и тем самым открывает следующий дубль, Studio повторяет проверку до устойчивого состояния. Конфликтующие строки переводятся в «Пропустить», а независимые корректные операции остаются доступными для Apply.
- Та же логика применяется после ручного review: исключение строки или отдельного поля больше не превращает локально возникший дубль в глобальную блокировку всего пакета. Конфликт, который нельзя однозначно связать с изменяемой Excel-строкой, по-прежнему блокируется fail-closed.
- После «Проверить изменения» доступен ручной «Скачать результат»: JSON `TESSA_MATRIX_PREVIEW_REPORT_V1` содержит итоговый reviewed-план, пропущенные строки и поля, выбранные исключения и текущую доступность Apply. Отчёт обновляется при изменении review и не выполняет запись в TESSA.
- Серверная ValidateDuplicate перед Apply и повторная проверка перед Store сохранены. Ошибка интервалов LeftOperandExtractor этим релизом не объявляется исправленной.

## 1.10.2 — 2026-09-04

- Добавлена ограниченная read-only диагностика серверной ошибки `LeftOperandExtractor is null`: после отклонённого контрольного `saved-rebuilt` выполняются три дополнительных duplicate-check варианта.
- В вариантах по одному меняется только сериализованная interval-строка исходящего запроса: удаляется `.changed`, `.state` или оба маркера. Значения `IntValue/IntToValue`, идентификаторы, роли и остальные строки не меняются.
- Исходная SDK-карточка не модифицируется; Store/Delete не вызываются, обычный Apply не меняется. Диагностика ограничена семью duplicate-check запросами и не запускает structural probes, если контрольная перестроенная строка уже проходит проверку.
- Это диагностический релиз, а не объявление исправления серверной ошибки. Результат нужен, чтобы определить минимальный structural trigger перед отдельным fix-PR.

## 1.10.1 — 2026-09-03

- «Собрать значения» — отдельная обычная кнопка без красной рамки.
- Выгрузка сохраняет названия из строк матрицы TESSA для организаций, сегментов, видов документов, исполнителей и остальных ссылочных полей. Справочник дополняется этими подписями по ID, включая тип роли.

## 1.10.0 — Справочники и объединение Excel

- Выбор ID и названия по ссылкам представления TESSA (`RefSection`, `ColPrefix`, `DisplayValueColumn`); убран подбор похожего источника. Разные ссылки одного представления не смешиваются. Кэш разделён по ссылке и версии правил; принудительное обновление отключает также кэш View API.
- Устранена перенумерация одноимённых вариантов при повторной нормализации и устаревший индекс поиска: видимый текст больше не подменяет выбранный элемент с тем же названием. Обновление сохраняет прежние селекторы и привязку переименованных значений.
- Каждая новая выгрузка обновляет справочники. «Обновить справочники в моём Excel» сохраняет рабочий лист, формулы, стили, исходные идентификаторы и пользовательские листы; обновляет только справочники и списки выбора.
- Новые выгрузки дополнительно хранят исходные значения ячеек. Объединение сохраняет непересекающиеся изменения, предлагает выбор при конфликте и отмечает серверные правки жёлтым. Старые книги без этих данных сохраняют консервативную защиту.
- Колонка «Действие» позволяет явно пометить новые строки при одновременном удалении и добавлении. Исходный baseline при обновлении берётся из TESSA, а не из локально изменённых значений.
- Автоматическое удаление учитывает только строки исходной выгрузки: строки, добавленные коллегами позже, сохраняются. Изменившиеся строки не удаляются без повторного выбора; замена ссылки или исполнителя с тем же названием определяется по ID.
- При конфликте удаления выбор «TESSA» сохраняет всю серверную строку. Восстановление удалённой на сервере строки совместимо с другими удалениями в Excel. Повреждённые служебные ID и fingerprint обнаруживаются до объединения.
- Сборщик значений выделен, поддерживает Enter, Esc, вставку прежнего набора и отдельный выбор для каждого поля. Добавлены свёрнутые пояснения о черновике, удалении и вводе.
- Диагностика проверяет названия справочников, подготовку очистки каждого заполненного поля и распознавание удаления; большие словари сохраняются частями. До 200 выбранных операций проверяются без записи.
- Отдельное действие применяет выбранный Preview с обычным подтверждением и сразу сверяет результат записи. Ошибка `LeftOperandExtractor` не обходится и остаётся открытой. [UAT и границы проверки](docs/UAT-v1.10.0.md).

## 1.9.51 — Проверки и диагностический ZIP одним кликом

- В «Дополнительно» добавлен свёрнутый раздел «Проверки и диагностика»: запустить проверки или сразу скачать результат одним ZIP. Повторное скачивание использует готовый результат; новый файл, Preview, Apply или смена матрицы не получают старую диагностику.
- Прогон проверяет среду, правила ввода, свежую схему, настройки матрицы/шаблона, чтение строк/справочников, экспорт и обратное чтение всех полей, выбранный Excel, сохранённую строку, её перестройку и несохранённую точную копию. До 20 ADD/UPDATE проверяются серверным поиском дубликатов.
- Изолированный bridge разрешает CardGet, получение заготовки CardNew, чтение справочников и два известных CardRequest. Store/Delete и неизвестные запросы запрещены; текущий Preview, отчёт Apply, receipts и кэш справочников не заменяются.
- Отмена оставляет частичный пакет в том же контексте; смена файла/матрицы останавливает прогон и не прикрепляет его к новому контексту. Сетевой отказ/таймаут останавливает следующие запросы. Ограничены запросы, проверяемые операции и объём захваченных данных; пропуски отражаются в отчёте.
- Пакет содержит рабочие значения, входной Excel, свежую выгрузку, схему, настройки, справочники, план, запросы/ответы и предыдущие отчёты, если доступны. Пароли, cookies, HTTP-заголовки и содержимое страницы не собираются. Private receipt semantic keys исключены.
- Добавлена регрессия реального коллектора и UI-обработчиков: точный дубль, отказ extractor, отсутствие записи, ZIP, повторное скачивание, двойной клик, отмена, переключение матрицы/файла, повреждённый файл, лимиты, таймаут и экранирование сообщений.
- Живая диагностика 1.9.50 от 02.09.2026 18:09 UTC: временных секций уже нет, оба ADD по-прежнему отклоняются. Выгрузка (19) совпадает с (17). **Ошибка интервалов не объявляется исправленной; Store и серверные транзакции этим прогоном не тестируются.**
