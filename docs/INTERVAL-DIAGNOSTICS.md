# Диагностика отказа интервалов

Этот инструмент собирает данные для исправления `LeftOperandExtractor is null`. Он не исправляет серверную настройку и не разрешает отклонённые добавления.

## Один запуск

1. Установите сборку 1.9.49, выберите рабочий Excel и нажмите «Проверить изменения».
2. После отказа интервалов раскройте **Дополнительно → Диагностика интервалов**.
3. Сохраните `TESSA_Interval_Diagnostics_….json`. Повторный клик скачивает тот же отчёт без новых запросов. Новая проверка Excel сбрасывает этот отчёт.

Проверка не вызывает Store или Delete, не меняет настройки матрицы и не запускает Apply. CardNew используется для получения несохранённой карточки добавления. Чужие строки не удаляются, диапазоны не заменяются другими значениями. «Отмена», смена матрицы, шаблона или выбранного файла прекращают следующие запросы; уже отправленный запрос может успеть завершиться.

Отчёт содержит значения проверяемых строк, внутренние ID, снимки хранилищ запросов перед сериализацией, ответы сервера и текст ошибки. Он создаётся только по кнопке. Передавайте его участникам диагностики; не прикладывайте исходный файл к публичному issue. Cookies, HTTP-заголовки авторизации, localStorage и содержимое остальных строк в отчёт не собираются. Это отдельный отчёт: результат предыдущего Apply остаётся доступен.

## Что сравнивается

| Образец | Источник | Назначение |
|---|---|---|
| `saved-original` | Свежий CardGet сохранённой строки с интервалом; карточка не перестраивается | Проверить отказ на сохранённых данных без влияния rebuildRowCard |
| `saved-rebuilt` | Клон этой карточки, те же ID и семантические значения после rebuildRowCard | Найти различия представления данных, внесённые Studio |
| `proposed-add` | Несохранённая новая карточка из первой отклонённой строки Excel | Зафиксировать фактическое добавление |
| `proposed-add` | Вторая отклонённая строка, если есть | Сопоставить два отказа |

`saved-original` — не автоматизация штатного редактора. Это тот же запрос проверки дубликатов на свежей карточке без перестройки значений. Выбор похожей контрольной строки применяется только в диагностике и не используется для сопоставления или записи.

Максимум: один CardGet, две подготовки CardNew и четыре проверки дубликатов. Повторных попыток нет. Каждый снимок запроса или ответа ограничен 2 МБ. Если семантика контрольной копии изменилась, она не отправляется: `rebuilt-control-differs`. Если копирование карточки недоступно, этот образец помечается `card-clone-unavailable`.

## Как читать результат

| Результат | Следующий шаг |
|---|---|
| `saved-original` уже возвращает `LeftOperandExtractor` | Ошибка воспроизводится без перестройки Studio; изучить серверный обработчик, настройки и сохранённую строку |
| Оригинал разрешён, `saved-rebuilt` отклонён | Сравнить секции, состояния строк, типы и служебные поля двух запросов |
| Обе проверки сохранённой строки разрешены, ADD отклонён | Проверить обработку новой версии и сочетания условий; сопоставить запрос со штатным созданием строки |
| Все образцы разрешены | Ошибка сейчас не воспроизвелась; нужна новая обычная проверка Excel, разрешение диагностики не переносится в Apply |
| `interrupted: true` | Отчёт частичный; причина остановки находится в `interruptionReason` |

`writesAttempted: 0` описывает этот сборщик, а не произвольные действия других пользователей или расширений TESSA. `requestSent` показывает, дошёл ли образец до вызова сервиса. Отсутствующий снимок ответа сопровождается `captureError`, если его не удалось сериализовать. Поля `outcome`, `code`, `message` отражают результат штатного метода validateDuplicate; сами образцы ничего не разрешают и не изменяют в плане.

## Подтверждённое состояние

Выгрузка (17) полностью совпала с (16): 21 строка / 546 рабочих ячеек. Локально итоговый Excel содержит 21 NOOP и 2 ADD. Живая проверка 1.9.48 отклоняет оба ADD до Store. Контроль через обычный редактор и серверный стек пока не получены; полного live PASS нет.

Контракт запроса и ранее выполненный разбор: [DUPLICATE-CHECK-DIAGNOSTICS.md](DUPLICATE-CHECK-DIAGNOSTICS.md).
