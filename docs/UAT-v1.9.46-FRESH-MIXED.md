# Проверка 1.9.46: отчёт и свежий смешанный UAT

«Скачать отчёт» перенесена в **Дополнительно**. Раздел по умолчанию закрыт и использует штатный [HTML details/summary](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/details). Его открытие не скачивает файл. Исправление `setControlDisabled` из 1.9.45 сохранено: после Apply, ошибки и сверки кнопка доступна. До первого отчёта она скрыта.

## Что установлено по исходному Apply JSON

| Поле | Значение |
|---|---|
| requestedCount / plannedCount / startedCount | 12 / 12 / 12 |
| appliedCount | 11 |
| preflightSkippedCount | 0 |
| storeSkippedCount / failedCount | 1 / 1 |
| cancelled / notStartedCount | false / 0 |
| sourceSkippedCount | 42 |
| Отдельные отклонённые поля | 4 |
| Обновление отображения | Успешно с первой попытки |

Невыполненная операция — ADD из Excel 35 прежнего UAT. Повторная `validateDuplicate` перед Store получила ответ TESSA `LeftOperandExtractor is null` при сравнении интервалов Int. Это не найденный дубль, не ручное исключение и не исчезновение после успешного сохранения: ошибка серверного обработчика проверки остановила строку **до Store**. Следующий ADD успешно продолжился.

Имя этапа `store-add` охватывает и эту проверку перед Store. Поэтому сам текст этапа не доказывает, что Store был вызван. Штатный web-клиент из присланной выгрузки использует тот же тип запроса и поля card/versionId/matrixId/templateID; Int-поля заполняются через IntValue/IntToValue. Оснований менять их на DecimalValue или отключать проверку нет.

Точный дефект обработчика/настройки сравнения требует серверного кода или диагностики соответствующей TESSA. В этом изменении он не объявлен исправленным. Приватные выгрузки, ID и справочники в GitHub не публикуются.

## Новый рабочий файл

`TESSA_UAT_MIXED_v1.9.46.xlsx` создан на базе свежей выгрузки (14), с её исходными ID, baseline и справочниками. Это рабочая матрица со встроенными правильными и ошибочными значениями; её можно выбрать в Studio. Старые файлы UAT не подменяют свежую базу.

| Изменить | 9 |
| Добавить | 3 |
| Удалить | 0 |
| Без изменений | 6 |
| Пропустить строки | 42 |

В книге 125 сценариев ввода, контроль 520 исходных ячеек, 78 ячеек новых строк и ручные проверки интерфейса, копирования, удаления, повреждения файлов, конфликтов и других шаблонов. Все статусы начинаются с NOT RUN. Все 26 рабочих полей строки 23 меняются; ошибки соседних строк не должны стирать прежние значения TESSA.

Новые ADD находятся в Excel 36, 37 и 39. Строка 37 отдельно проверяет случай нескольких значений и сравнения интервалов. Цель — сохранить все 12 операций. Если сервер снова вернёт LeftOperandExtractor, поставить **BLOCKED** для соответствующего ADD, сохранить отчёт через «Дополнительно», сверить реально выполненные операции. «Подтверждено 11 из 11» при Apply 11 из 12 не является полным PASS.

Пустые строки 35/40 не создают операций. Неверные значения каждого рабочего поля находятся в строках 41–66, текстовые ссылки/HTML/SQL/DDE и безвредные арифметические формулы — в 67–76. Настоящие формулы-провокации используют только `=1+1`; внешние адреса — example.invalid. Повреждение ZIP, чужая матрица и сломанный baseline проверяются отдельно на копиях: такие файлы нельзя считать пригодными для частичного применения.

## Порядок

1. Установить 1.9.46 и открыть исходную тестовую матрицу.
2. Прочитать «Старт проверки», выбрать эту книгу, выполнить Preview и сверить счётчики.
3. Проверить ошибки, выбор отдельных полей и строк; вернуть полный выбор перед общим проходом.
4. Выполнить Apply, записать фактическое число выполненных операций и причины отказов.
5. Открыть «Дополнительно → Скачать отчёт», сохранить JSON. Выполнить «Проверить результат» и убедиться, что отчёт остаётся доступен.
6. Скачать свежий Excel. Сверять исходные строки по служебным ID, новые — по диапазонам 801..809, 810..819, 820..829 и всем остальным полям. Номера строк свежего Excel могут отличаться от UAT.
7. После изменения матрицы не применять старый пакет повторно; последующие отдельные проверки делать со свежей выгрузкой.

Отсутствующие в этом шаблоне типы отмечаются N/A. Клиентская автоматика проверяет несколько структур и типов; серверные правила каждой корпоративной матрицы требуют отдельного живого прогона.
