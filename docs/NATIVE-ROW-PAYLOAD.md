Все четыре запроса содержат `IntValue / IntToValue` типа `int`, а не дату или Decimal. Границы упорядочены; OwnerRowID соответствует запрошенной версии. После перестройки сохранённой строки прежние значения помечены Deleted, новые — Inserted, активные условия совпадают. У Excel 36 по сравнению с контрольной строкой изменён один критерий — интервал; набор исполнителей также отличается. Это не опыт, в котором менялся только один параметр.

Успешные проверки сохранённой версии не доказывают исправность сравнения двух различных интервалов: обработчик может исключать саму проверяемую версию по её ID. Серверный стек и результат штатного добавления отсутствуют.

## Найденное отличие и изменение кода

В предоставленном клиентском модуле `route_matrix` метод `restoreActualValues` переносит изменения из виртуальных таблиц в Values/Roles, затем удаляет пять временных секций. Он вызывается перед проверкой дубликатов и Store. Studio создаёт Values/Roles напрямую, но до 1.9.50 отправлял оставшиеся пустые виртуальные секции. В живом JSON CardGet содержит `Rows:null`, CardNew — `Rows:[]`.

`TessaBridge.prepareRowCardForServer` устраняет это отличие:

1. Проверяет только пять известных временных секций матрицы. Остальные, включая пользовательские секции с `Virtual` в названии, сохраняет.
2. При непустом/некорректном буфере останавливает операцию до запроса. Studio не отбрасывает и не переносит чужие правки штатного редактора.
3. Использует отдельную SDK-копию карточки и удаляет из неё пустые секции. Исходную карточку не изменяет.
4. Одинаково подготавливает карточку для `validateDuplicate` и `storeRowCard`.

Не меняются ID, версии, поля условий и ролей, типы/границы интервалов, состояния Inserted/Deleted, права и version guard. Ошибка сервера по-прежнему запрещает Store; нет повторов с ослабленными условиями, подмены versionId или локального разрешения вместо `ok=true`.

`Card.clone`, `getStorage` и коллекция секций — штатные API: [Card](https://mytessa.ru/docs/4.1/web/classes/Platform.Cards.Card.html), [StorageMap](https://mytessa.ru/docs/4.1/web/classes/Core.Storage.StorageMap.html). Эти общие API не документируют корпоративный обработчик проверки дубликатов.

## Что проверено

Новый регрессионный тест `tests/native-row-payload.mjs` до изменения кода падал на лишних временных секциях. После изменения проверяет оба вида пустого буфера, совпадение данных проверки и Store, неизменность исходной карточки, сохранение типизированного интервала, запрет непустых буферов, отсутствие повторов и сохранение отказа сервера.

Дополнительно на всех четырёх приватных карточках из JSON локально выполнено тело `restoreActualValues` из приложенного клиентского модуля. Использовался адаптер хранилища; весь сайт и сервер не запускались. Для пустых виртуальных буферов результат новой подготовки совпал с результатом штатного метода по всему хранилищу карточки. Значения, состояния и идентификаторы сохранены. Исходные JSON не включены в публичный репозиторий.

**Это подтверждает исправление различия формата запроса, но ещё не устранение `LeftOperandExtractor` на сервере.** Повторного живого ответа для 1.9.50 нет. Сборка остаётся кандидатом, не основанием для релиза.

## Проверка в TESSA

1. Установить 1.9.50 и повторить Analyze прежнего `TESSA_FINAL_v1.9.47.xlsx`. Не выполнять Apply старого Preview.
2. Если обе серверные проверки проходят, ожидается 21 строка без изменений и 2 добавления. Просмотреть их; после Apply выполнить «Проверить результат» и сверить свежий экспорт.
3. Если `LeftOperandExtractor` остаётся, скачать диагностику 1.9.50: она фиксирует уже подготовленные запросы без временных секций. Повторять Apply нельзя: это не средство обхода отказа.

При сохраняющемся отказе требуется серверный обработчик requestType `f5c0419f-15cc-428e-b2f9-76c1b3ef7525` и место выбора `LeftOperandExtractor` для источника настройки + Int + Interval + Equality. Следует воспроизвести добавление второй строки с интервалом при существующей первой; проверить разные/равные/пересекающиеся интервалы и возвращать явный результат проверки. Не менять тип Int на Decimal только из-за текста исключения.
