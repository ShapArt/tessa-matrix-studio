# Проверка скачивания отчёта — 1.9.45

После создания отчёта внутри Apply кнопка становилась доступной, но `setBusy(false)` восстанавливал её исходное `disabled=true`. Следующая проверка результата сохраняла эту блокировку. Наличие имени JSON в подсказке подтверждало создание отчёта, но скачать его было нельзя. Такое поведение `disabled` соответствует [контракту HTMLButtonElement](https://developer.mozilla.org/en-US/docs/Web/API/HTMLButtonElement/disabled); ошибка была в управлении состоянием Studio.

Исправление сохраняет актуальное состояние кнопки во время операции и восстанавливает его после завершения. Так же обработана кнопка ручного обновления отображения. Логика Apply, проверка прав, состав изменений и содержимое отчёта не менялись.

## Проверка

| Сценарий | Ожидание |
|---|---|
| До первого Apply | «Скачать отчёт» скрыта; пустой JSON не скачивается |
| Apply выполняется | Кнопки заблокированы; автоматического скачивания нет |
| Apply завершён полностью или частично | «Скачать отчёт» доступна, один клик скачивает один JSON с результатом этой операции |
| Остановка или ошибка Apply | Итоговый Apply/ErrorReport доступен после завершения операции |
| «Проверить результат» завершилось успешно | Исходный Apply JSON по-прежнему доступен и не заменён результатом сверки |
| Сверка не завершилась | Исходный Apply JSON по-прежнему доступен |
| Автообновление отображения не удалось | «Обновить отображение» доступна после завершения Apply |
| Ручное обновление прошло успешно | Его кнопка скрыта и заблокирована; скачивание отчёта доступно |
| Другие кнопки были заблокированы до операции | Пустой picker и недоступная страница остаются заблокированными |

Автоматическая регрессия сначала упала на `completed Apply left its report button disabled`, затем прошла после исправления. Тест вызывает настоящий `applyPlan` на mock-мосте, завершает цикл UI и сверяет скачанный Blob с исходным JSON. Это проверка кода, не выполнение Store во внутренней TESSA.

## Сохранение уже готового отчёта из старой версии

Отчёт хранится только в памяти вкладки. До обновления Studio или перезагрузки страницы его можно сохранить так:

1. Дождаться окончания текущей операции.
2. Открыть F12 → Console и выполнить:

   ```js
   document.querySelector('#tms-download-report')?.removeAttribute('disabled');
   ```

3. Нажать «Скачать отчёт» в Studio.

Команда изменяет только HTML-состояние этой кнопки. Она не применяет Excel, не вызывает Store и не меняет данные TESSA. Если вкладка уже перезагружена, старого отчёта в памяти больше нет; повторный Apply не восстанавливает его.

## Живой прогон

Новый скрин пользователя показывает «применено 11 из 12» и «Подтверждено: 11 из 11». Это подтверждает успешную сверку выполненных операций, но не объясняет, почему одна из запрошенных операций не выполнена. Причину нужно взять из исходного Apply JSON. Предыдущая [сверка выгрузки](UAT-v1.9.44-PICKER-AUDIT.md) показала отсутствие одного ADD при совпадении всех исходных 468 ячеек с ожидаемым результатом. Полный live PASS пока не установлен.
