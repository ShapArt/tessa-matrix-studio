# Проверки и диагностика

Для диагностики не нужно собирать запросы вручную или нажимать Apply.

1. Установите 1.9.51 и откройте нужную матрицу.
2. Выберите тот Excel, с которым возникла проблема. Предварительно проверять изменения не обязательно.
3. Откройте **Дополнительно → Проверки и диагностика → Скачать пакет диагностики**.

Studio выполнит проверки и скачает один `TESSA_Diagnostics_….zip`. Передайте ZIP для разбора. Он содержит рабочие значения, включая выбранный Excel и настройки матрицы/шаблона. Без выбранного файла проверяется сама матрица; этапы изменения Excel будут отмечены «Не проверено».

**Запустить проверки** выполняет новый прогон без скачивания. **Скачать пакет диагностики** скачивает уже готовый результат, если файл, Preview и матрица не изменились. Для проверки после внешнего изменения данных нужен новый прогон. Кнопка «Отмена» останавливает следующие запросы; уже отправленный запрос может завершиться. В том же контексте доступен частичный пакет. При переключении матрицы, шаблона или файла старый результат сбрасывается.

## Что проверяется

| Этап | Что означает «Пройдено» |
|---|---|
| Подключение и возможности TESSA | Открытая матрица определена, необходимые API найдены |
| Правила ввода | Числа, отрицательные/дробные интервалы, Да/Нет и отбрасывание некорректного ввода прошли локальные проверки |
| Схема и настройки | Получены структура, карточка матрицы и карточка шаблона с доступными текущему пользователю данными |
| Строки | Прочитан состав матрицы; у строк есть уникальные служебные идентификаторы |
| Справочники | Доступные справочники перечитаны без замены рабочего кэша |
| Выгрузка → обратное чтение | Все выгруженные строки и поля дали «Без изменений», без пропусков |
| Выбранный Excel | Planner разобрал файл без блокировок, пропущенных строк и ошибочных полей |
| Сохранённая строка | Сервер разрешил проверку её существующей версии |
| Та же строка после перестройки | Типизированные значения сохранились; сервер разрешил проверку |
| Точная несохранённая копия | Сервер вернул явный результат «дубль»; копия не сохранялась |
| ADD/UPDATE из Excel | Проверка дубликатов пройдена для указанной операции; запись не выполнялась |

Для контрольной строки выбирается первая строка с интервалом; если таких нет — первая строка. Точная копия отличается новыми ID карточки и версии. Это позволяет проверить реальное сравнение с другой строкой, чего не доказывает успешная проверка той же сохранённой версии.

«Ошибка» означает неуспешный этап, «Не проверено» — отсутствие данных, лимит или прерванный прогон. Некорректные ячейки дают ошибку этапа Excel, но корректные ADD/UPDATE могут пройти отдельные серверные проверки. При бизнес-отказе сохраняются запрос/ответ и результаты других этапов. При транспортном отказе или таймауте следующие запросы прекращаются.

**Сохранение, удаление, транзакции, параллельная запись и работа штатного редактора этим разделом не тестируются.** Даже полностью зелёный результат означает только успешность описанных проверок без записи. Для Apply по-прежнему нужны обычный свежий Preview, серверная проверка и контроль версии; после записи — «Проверить результат» и свежий Excel.

## Что лежит в ZIP

| Файл | Содержание |
|---|---|
| `report.json` | Версия, контекст, этапы, статусы, ограничения, перечень захваченных/пропущенных файлов |
| `requests/` | Хранилища запросов CardGet/CardNew/CardRequest и ответы; параметры/результаты чтения справочников |
| `matrix-card.json`, `template-card.json` | Доступные настройки матрицы и шаблона |
| `structure.json`, `snapshot.json`, `dictionaries.json` | Схема, строки с типами/ID и справочники |
| `matrix-current.xlsx` | Свежая выгрузка, если экспорт удался |
| `selected.xlsx`, `selected-workbook.json`, `selected-plan.json` | Выбранный файл, результат чтения и локального сравнения |
| `input-rules.json`, `roundtrip.json` | Локальные проверки правил ввода и экспорта |
| `previous-state.json` | Предыдущий Preview, отчёт Apply, результат reconciliation и старая диагностика, если есть |
| `README.txt` | Краткая инструкция по пакету |

Некоторые файлы могут отсутствовать: причина будет в `checks` или `omitted`. Сбор ограничен 2000 обёрнутыми запросами, 20 операциями ADD/UPDATE, 8 МиБ на файл и 48 МиБ суммарно до ZIP. Таймаут обёрнутого сетевого запроса — 20 секунд. Весь Excel проходит локальный разбор; превышение лимита серверных проверок не означает, что остальные операции проверены. Нативное представление читает страницы штатным механизмом Studio; его внутренние HTTP-запросы не являются полным сетевым trace и не входят в этот счётчик.

Прогон не собирает HTTP-заголовки, cookies, пароли, browser storage или HTML страницы. Private semantic keys из mutation receipts исключаются. Сырые бизнес-запросы содержат значения карточек и предназначены для выбранного пользователем диагностического пакета; обычный отчёт Apply сохраняет прежнюю фильтрацию.

## Проверка самой функции

Автоматика: `node tests/studio-diagnostics.mjs`, затем `npm test`. Тесты выполняют реальные функции планирования, XLSX, перестройки карточки и обработки кнопок с искусственными ответами TESSA. Проверяют отказ интервалов, контрольный дубль, отсутствие Store/Delete, ZIP, сохранение исходных объектов, кэш, отмену, смену контекста, ошибки файла, лимиты и экранирование сообщений.

Живая проверка: выбрать проблемный Excel → скачать ZIP → открыть `report.json`. Для текущего отказа ожидаются отдельные результаты сохранённой строки, её перестройки, точной новой копии и Excel 36/37. Повторное скачивание не должно вызывать новых запросов. Смена матрицы/файла в процессе должна остановить прогон, а не сохранить старой матрице новый результат. Во время прогона не должно быть Store/Delete.

Контракты платформы: [CardRequest](https://mytessa.ru/docs/4.1/web/classes/Platform.Cards.Service.CardRequest.html), [CardNewRequest](https://mytessa.ru/docs/4.1/web/classes/Platform.Cards.Service.CardNewRequest.html). Корпоративный обработчик проверки дубликатов этими страницами не описан. Его ошибка `LeftOperandExtractor` в 1.9.50 воспроизводится; 1.9.51 добавляет диагностику и не объявляет её исправленной.
