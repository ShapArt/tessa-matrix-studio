# Устройство TESSA Matrix Studio

Документ нужен тем, кто будет сопровождать userscript. Пользователю для ежедневной работы он не требуется.

## Общий принцип

Код намеренно остаётся одним userscript-файлом, чтобы установка и обновление через Tampermonkey не требовали сборки. Внутри файл разделён на независимые логические слои.

## Разделы кода

1. **Состояние и константы** — версия, параметры roundtrip, идентификаторы секций и запросов TESSA.
2. **Базовые утилиты** — нормализация, даты, числа, сравнение и сериализация.
3. **XLSX reader** — разбор ZIP/XML рабочего файла без внешней библиотеки.
4. **XLSX writer** — формирование выгрузки, стилей, инструкции и служебных ID.
5. **Справочники** — кэш, нормализация, разрешение ID/названий.
6. **Roundtrip Excel** — сборка пользовательской книги, инструкции и скрытых identity-полей.
7. **TessaBridge** — единственная прослойка для обращения к внутренним API TESSA.
8. **Схема Excel** — сопоставление колонок Excel с критериями/функциями матрицы.
9. **Planner** — расчёт `update/add/delete/noop/skip`, включая `position-overwrite`.
10. **Safety / preflight** — права, режим редактирования, дубли, справочники, защита от удаления.
11. **Analyze / apply** — пользовательская последовательность проверки и записи.
12. **UI** — панель, diff и progress.

## Ключевые инварианты

### Identity важнее текста

Существующая строка должна сопоставляться по `MatrixRowID / MatrixVersionID`. Текстовое сходство не является основанием для автоматического изменения существующей строки.

### Копия в новую строку и копия поверх строки — разные операции

- новая свободная строка -> `ADD`;
- копия поверх существующей позиции -> `UPDATE` целевой identity с пометкой `position-overwrite` / **ЗАМЕНИТЬ**.

### Неоднозначность не исправляется догадкой

Если справочник, identity или соответствие строки нельзя определить однозначно, строка должна перейти в `SKIP` или план должен быть заблокирован.

### Preview и Apply разделены

`Проверить изменения` строит план без записи. `Применить` работает с уже построенным планом и повторно запускает preflight.

### Права TESSA остаются источником истины

Userscript не должен создавать обход штатных проверок режима редактирования и прав пользователя.

## Версионирование

Используется SemVer-подобная схема:

- `PATCH` — исправления, документация, совместимость без изменения пользовательской модели;
- `MINOR` — новая пользовательская возможность или изменение сценария;
- `MAJOR` — несовместимое изменение формата roundtrip/архитектуры.

Перед публикацией новой версии:

1. изменить `@version` и `APP.version`;
2. обновить `CHANGELOG.md`;
3. выполнить синтаксическую проверку;
4. прогнать regression-тесты;
5. проверить установку userscript по raw-ссылке;
6. проверить preview на чистой выгрузке, изменении, добавлении, замене и удалении;
7. только после этого обновлять `main`.

## Автообновление

Metadata указывает на:

```text
https://raw.githubusercontent.com/ShapArt/tessa-matrix-studio/main/tessa-matrix-studio.user.js
```

Поэтому файл в `main` считается стабильной версией.

## Проверка перед релизом

В репозитории нет тестовых выгрузок из рабочих матриц. Автотесты создают минимальную синтетическую матрицу в памяти, поэтому для проверки не требуются реальные данные TESSA.

```bash
npm test
```

Команда проверяет:

- синтаксис userscript;
- metadata, автора, домен и update/download URL;
- базовую нормализацию значений;
- чистый Excel без изменений;
- копирование строки в новую позицию как `ADD`;
- вставку копии поверх существующей строки как `position-overwrite` / **ЗАМЕНИТЬ**;
- физическое удаление строки как `DELETE`.
