# Проверка TESSA Matrix Studio 1.9.42

Версия проверяет подключение автоматически, сокращает основной экран до последовательных действий и добавляет сбор нескольких значений для одной ячейки. Диапазоны и сохранение корректных полей из 1.9.41 остаются в этой сборке.

## Что подготовлено

Приватный пакет сделан по свежей выгрузке `(9)`. Рабочие значения, справочники и служебные идентификаторы не публикуются в GitHub. Он содержит:

| Файл | Ожидание на исходном состоянии |
|---|---|
| `00_UAT_CHECKLIST.xlsx` | 107 сценариев и 468 проверок ячеек; всего 575 отметок |
| `01_ACTIVE_ALL_FIELDS.xlsx` | 6 UPDATE, 12 NOOP; изменения всех 26 рабочих полей |
| `02_PREVIEW_ONLY_INVALID_FIELDS.xlsx` | 1 UPDATE, 7 SKIP, 10 NOOP; одно неверное поле исключено из UPDATE |
| `03_PREVIEW_ONLY_ADD.xlsx` | 1 ADD, 18 NOOP |
| `04_PREVIEW_ONLY_DELETE.xlsx` | 1 DELETE, 17 NOOP |
| `05_PREVIEW_ONLY_BAD_BASELINE.xlsx` | 1 SKIP, 17 NOOP |

Чеклист не является матрицей: Studio должен отклонить его с понятным сообщением. В Studio загружаются остальные пять файлов. Их планы подтверждены production-парсером и planner; скрытый baseline сохранён.

Сначала проверьте **все PREVIEW_ONLY без применения**, пока матрица ещё совпадает с исходной выгрузкой. После Apply состояние изменится и прежние счётчики больше не обязаны повторяться. Не отключайте проверку устаревших данных, чтобы получить «нужные» цифры.

## 1. Подключение и интерфейс

1. Откройте Studio до открытия карточки. Ожидается «Откройте матрицу».
2. Откройте матрицу. При загрузке ожидается «Матрица загружается», затем «Матрица готова» без ручного повтора.
3. Закройте и снова откройте панель; перейдите на другую вкладку. В закрытой панели и скрытой вкладке монитор не проверяет среду. Он никогда не вызывает CardService.
4. Создайте Preview и перейдите в другую матрицу. Старые план, выбор полей, словари и проверка результата должны сброситься. Повторите со сменой TemplateID той же карточки.
5. Без выбранного файла проверка недоступна. «Дополнительно» раскрывает обновление справочников, обновление полей и сбор значений. «Отмена» появляется только во время операции, применение — после проверки.
6. Проверьте клавиши Tab, Enter, Space, видимость фокуса и ширину окна 320/768/1024/1440 px. Длинный текст не должен закрывать действия.

## 2. Несколько значений

1. Скачайте Excel или выберите рабочую книгу.
2. Откройте «Дополнительно → Собрать значения для ячейки».
3. Выберите поле. Найдите и отметьте два варианта, затем измените поиск: выбор должен сохраниться.
4. Нажмите «Скопировать». В Excel войдите в нужную ячейку через **F2**, затем **Ctrl+V**. Значения должны остаться в одной ячейке.
5. Сохраните книгу, выполните проверку. Оба элемента должны соответствовать точным записям справочника.
6. Проверьте снятие галочки, очистку, смену поля, одноимённые роли разных типов, запрет буфера обмена и закрытие панели во время копирования.

При ручном вводе используйте Alt+Enter. Обычный Excel dropdown выбирает один элемент. Подсказки о формулах и разделителях нельзя обходить: неоднозначный текст требует точного сопоставления, а не угадывания.

## 3. Поля и ошибочные действия

Лист `01_ACTIVE` перечисляет 34 подготовленные правки. Лист `04_CELLS` содержит все 26 × 18 рабочих ячеек с исходным и ожидаемым содержимым. При частичном Apply проверяйте изменения только выбранных строк; остальные должны сохранить исходное состояние.

Отдельно покрыты ноль, пустое значение, диапазоны `4-15`, `4..15`, `4 – 15`, две границы, справочники, несколько ролей и логические значения. Негативы проверяют дробное/переполненное целое, обратный диапазон, неизвестный справочник, формулу, логический диапазон и повреждённую подпись.

В точно сопоставленном UPDATE неверное поле сохраняет текущее значение; остальные корректные поля могут применяться. ADD, замена строки и нарушенные идентификаторы проверяются целиком. Причины исключения должны быть видны до записи.

## 4. Применение и результат

1. В ACTIVE проверьте все поля и оставьте одну тестовую строку через «Выбрать часть изменений» либо исключение строк.
2. Подтвердите применение. Проверьте счётчики записанных и исключённых операций.
3. Повторный Apply старого плана должен быть недоступен.
4. Нажмите «Проверить результат»: все записанные строки подтверждены; дополнительных Store/Delete нет.
5. Скачайте свежий Excel и сверьте каждую применённую ячейку по `04_CELLS`.
6. Повторная проверка исходного ACTIVE должна предлагать только ещё не применённые изменения.
7. Измените применённую строку штатно. Повторная проверка результата должна обнаружить расхождение без автоматического исправления.

## 5. Другие шаблоны

Для другой матрицы нужен её собственный свежий Excel. Повторите небольшой UPDATE для каждого доступного типа поля и проверьте результат. Универсальность проверяется по структуре и типам, а не по переносу приватного файла ОРД в другую карточку.

Автоматика `tests/multi-template-roundtrip.mjs` покрывает три независимых шаблона, восемь типов данных, переименование/перестановку полей, чужой файл и смену шаблона перед preflight. `tests/runtime-monitor-integration.mjs` проверяет очистку состояния при смене карточки/шаблона, в том числе во время операции, без серверных запросов и пересборки плана.

## Доказательства и границы

Последний предоставленный Apply-отчёт содержит 6 успешных UPDATE. Повторный planner для изменённой книги `(8)` относительно свежего состояния `(9)` даёт 18 NOOP и 0 повторных UPDATE. Это подтверждение по переданным файлам, а не запись из нашей среды.

Сохранённая HTML-страница из ZIP содержит Studio **1.9.38**. Она полезна для проверки разметки и контрактов JS-модуля матрицы, но не подтверждает установку 1.9.42 или её работу на сервере. Браузерный вид новой панели и live Store в корпоративной TESSA остаются пунктами живого UAT. Автоматические тесты не заменяют эти отметки.
