## Доказанная причина

1. `ViewRequest.addParameter(name, callback)` ищет `name` в метаданных самого запроса и бросает `Can not add parameter with name 'MatrixID'.`, если параметра нет. Matrix view получает динамические метаданные при инициализации контрола; статические метаданные service view не гарантируют наличие MatrixID.
2. Настоящая сигнатура builder — `addCriteria(operator, text, value)`. V13 передавал `value, undefined`: даже устранение первой ошибки не сделало бы запрос корректным.
3. `ViewCriteriaValue.serializeToStorageCore` требует тип из метаданных параметра. Добавления одного имени через `withName` недостаточно: нужны GUID для MatrixID и Int32 для PageLimit/PageOffset.
4. V13 сохранял лишний guard на наличие `createDataRequest` и временно присваивал `currentPage/pageLimit`. Наличие helper не нужно самостоятельному запросу; даже восстановленное присваивание может запустить реакцию UI.

Это подтверждено кодом из предоставленного platform bundle: модули 263622, 192632, 155431, 58283, 378129 и 857377. Публичный facade 660623 экспортирует ViewParameterMetadata и SchemeType. Данные организации в воспроизводимые тесты не перенесены.

## Исправление

- Используется overload `addParameter(callback)` и отдельный native ViewParameterMetadata для каждого из трёх параметров.
- Типы задаются через native SchemeType.Guid / SchemeType.Int32; text и value передаются в правильном порядке.
- Запрос сохраняет one-based offsets 1, 51, 101 и lookahead limit 51 при странице 50 строк.
- Рабочий самостоятельный путь не вызывает mounted helpers и не меняет свойства страницы.
- Проверки повторной страницы, полноты membership, наличия identity-колонок и fallback сохранены.
- Build в ошибке UAT берётся из актуальной диагностики paging, а не только из старого общего fingerprint V4.
- Существующий последний transform исправлен на месте; новый слой патчей не добавлен. Формат диагностики остаётся V13, сборка определяется новым `TMS_V1_16_13_TYPED_PAGING_RUNTIME_CONTRACT` и версией 1.16.13.

## Репозиторий и достоверность тестов

Production-код — большой userscript; кандидат собирается последовательностью hotfix transforms. `main`, исходный JS и готовый кандидат имеют разные версии. Проверять только корневой JS недостаточно. Исторические paging-тесты в основном искали строки/маркеры и потому не ловили неверный overload, порядок аргументов и сериализацию.

Добавлен `tests/native-paging-runtime-contract.mjs`: он исполняет метод из полностью собранного кандидата, проверяет типизированные значения запроса, 103 уникальные строки, отсутствие transient UI writes, отсутствие зависимостей от mounted helpers, пустую матрицу и границы страниц, отказ при повторе страницы/отсутствии MatrixID/ошибке сериализации/отсутствии identity. Он входит в `npm test` и проверку точного CI-артефакта.

Три исторических теста теперь сверяют provenance с реальной metadata-версией кандидата вместо постоянно расширяемого списка номеров версий. Ни один существующий тест не удалён или отключён.

На Windows были отдельные проблемы: CRLF ломал точные строковые transforms, `URL.pathname` давал неверный файловый путь, а четыре CLI-transform молча не запускались. Зафиксированы LF и преобразование URL через `fileURLToPath`. Правки переносимости выделены в отдельный коммит.

## Следующая проверка без CRUD

После установки 1.16.13 и перезагрузки страницы на той же тестовой матрице достаточно вызвать прямое чтение. Метод ниже не вызывает Store/Delete и не запускает Full UAT:

```js
const E = window.__TESSA_MATRIX_SYNC_EXPORTS__;
if (E?.studioVersion() !== '1.16.13') throw new Error('Нужна версия 1.16.13');
const bridge = await E.TessaBridge.create();
const result = await bridge.collectNativeMatrixViewLinksServerPaged({ pageLimit: 50 });
console.log({
  version: E.studioVersion(),
  serverPaging: result?.serverPaging === true,
  rows: result?.links.length,
  pages: result?.pagesVisited,
  diagnostics: bridge.lastServerPagingDiagnostics,
});
```

Для неизменённой тестовой матрицы ожидаются `serverPaging: true`, 103 строки, страницы `[1, 2, 3]`, `status: passed`, актуальный build. Если runtime не поддерживает нужные классы, ошибка остаётся явной; отсутствие live-проверки нельзя объявлять 50/50 PASS.
