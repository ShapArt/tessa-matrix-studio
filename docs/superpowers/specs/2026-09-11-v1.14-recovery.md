# v1.14 Recovery Design

## Goal

Stabilize the v1.14 release candidate around one canonical live UAT, deterministic matrix identity, explicit ambiguity/conflict resolution, reliable browser downloads, refreshed dictionaries/three-way merge, exhaustive writable-field mutation checks, button-level functional UAT, and guaranteed restoration of destructive tests.

## Approved sequence

1. canonical UAT
2. matrix identity
3. resolver / Kireeva ambiguity
4. Resolution Center
5. real download test/fix
6. dictionary refresh + three-way merge
7. every-field live mutation
8. every-button UAT
9. destructive restore
10. full regression
11. new exact RC

## Safety invariants

- Production `main` and released v1.13.0 remain untouched until the v1.14 RC is fully verified.
- Full UAT is shipped in the canonical Studio userscript; it is not an optional overlay.
- Studio roundtrip identity is driven by `MatrixID` / `TemplateID`; fuzzy name matching is legacy fallback only.
- Ambiguous employee/function values never auto-apply. They must be resolved explicitly or skipped explicitly.
- Apply success is green only when there are no unresolved or silently skipped user edits.
- Functional download tests assert an actual downloadable artifact, not merely XLSX builder output.
- Three-way merge uses BASE / MINE / TESSA and never silently overwrites divergent edits.
- Live field mutation tests choose deterministic alternative valid values and verify read-back.
- Every destructive live UAT step records cleanup work and finishes with baseline-equivalent state, otherwise the run is UNSAFE.
- Existing stale/version/duplicate/preflight/native-store/read-back guards remain intact.

## UX decisions

### Resolution Center

For each ambiguous or conflicting field show the original/base value, local Excel value, current TESSA value where applicable, and actions:

- Keep mine
- Use TESSA
- Choose another current dictionary value
- Skip explicitly

Employee choices retain RoleID/RoleTypeID as identity; display text is not identity.

### UAT result states

- PASS: required behavior verified.
- FAIL: behavior executed but result is incorrect.
- NOT RUN: no safe candidate exists or capability is unavailable.
- UNSAFE: cleanup/restoration could not be proven.

A run with unresolved user changes or failed cleanup cannot report success.
