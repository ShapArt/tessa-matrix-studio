# v1.9.15 QA Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve physical Excel deletions through schema refresh, harden release immutability/delivery monitoring, and add a matrix-bound QA workbook generator that produces directly uploadable positive and negative test scenarios.

**Architecture:** Keep the existing single-userscript architecture and add focused pure helpers with regression coverage. QA files must be generated from the currently open matrix snapshot so their MatrixID/TemplateID and hidden identities are valid for that matrix. Release workflow changes stay isolated from runtime behavior.

**Tech Stack:** JavaScript userscript, Node.js regression tests, GitHub Actions, existing in-script XLSX reader/writer.

**Spec:** User request on 2026-08-27 plus existing README roundtrip semantics: physical row deletion means DELETE; ambiguous identity must refuse/skip rather than guess.

## Global Constraints

- Current baseline version: `1.9.14`; target release: `1.9.15`.
- Do not mutate the user's source Excel during preview/review.
- Physical deletion in a roundtrip workbook must remain an intended deletion after `Актуализировать Excel-схему` when the source row is still unchanged in TESSA.
- If the deleted source row changed in TESSA after export, schema refresh must refuse rather than silently preserve or rebase the deletion.
- Release assets for an already published tag must never be overwritten.
- QA workbooks must be tied to the current matrix and generated from a fresh snapshot; synthetic MatrixID/TemplateID files are not presented as live-uploadable.
- Corporate provisioning is out of scope.
