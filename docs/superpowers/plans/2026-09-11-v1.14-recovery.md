# v1.14 Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn v1.14 into a single verifiable RC whose installed userscript contains the full live UAT and whose critical user workflows are tested end-to-end.

**Architecture:** Keep the existing single-userscript runtime and safety guards. Consolidate test instrumentation into the canonical userscript, then harden identity/resolution and expose a single conflict-resolution surface shared by preview, dictionary refresh, and three-way merge. Functional UAT drives the same production functions and browser-facing download path as users.

**Tech Stack:** JavaScript userscript, Node.js contract tests, jsdom, GitHub Actions, TESSA CardService/native editor bridge, XLSX/OpenXML helpers already in repository.

**Spec:** `docs/superpowers/specs/2026-09-11-v1.14-recovery.md`

## Global Constraints

- Do not modify released v1.13.0.
- Work from `feat/incremental-performance-v1.14` through isolated recovery branch.
- TDD: failing contract first for every production behavior change.
- Do not weaken stale/version/duplicate/preflight/native-write/read-back guards.
- Full UAT cleanup must prove baseline-equivalent state or return UNSAFE.
- No release/merge to main until live RC UAT passes.
