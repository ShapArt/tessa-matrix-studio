# Корпоративное развёртывание TESSA Matrix Studio

Пакет содержит расширение Manifest V3 со встроенной проверенной сборкой Studio.
Tampermonkey для этого варианта не нужен. Скрипт запускается только на перечисленных
HTTPS-хостах, в основном фрейме. Дополнительных API-разрешений, фонового обработчика,
внешних исполняемых зависимостей и загрузчика кода нет. Контекст `MAIN` нужен для
штатного API TESSA; он не изолирует расширение от JavaScript самой страницы.
[Контексты content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts).

## Подготовка пакета

Сначала собрать и проверить итоговый userscript:

```text
node tools/build-paging-candidate.mjs dist/tessa-matrix-studio.user.js
npm test
node tools/build-enterprise-package.mjs dist/tessa-matrix-studio.user.js deployment/enterprise-config.example.json dist/enterprise
```

Выходной каталог должен быть новым или пустым. Сборщик не перезаписывает старые
релизы. `extension/studio.js` совпадает с переданным userscript побайтно; хеши
находятся в `BUILD.json` и `SHA256SUMS.txt`. Пакет без конфигурации обновлений
пригоден для локального пилота через «Загрузить распакованное расширение».
Это **не подписанный CRX и не выполненное доменное развёртывание**.

## Заявка администраторам

Указать владельца приложения, согласующего ИБ, тестовую OU/группу устройств,
браузер и его корпоративную версию, утверждённые адреса TESSA и HTTPS-сервер
обновлений. Выделить отдельные группы пилота и промышленного контура.

Администратор упаковывает каталог `extension` в CRX средствами браузера и хранит
PEM-ключ в корпоративном хранилище секретов. Ключ нельзя прикладывать к заявке,
ZIP с исходниками или коммитить. Сохранение того же ключа сохраняет ID расширения
при обновлениях. Это штатный процесс
[самостоятельного размещения расширения Edge](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-manage-extensions-webstore).

После получения настоящего ID создать локальный конфиг на основе примера и добавить:

```json
{
  "origins": ["https://tessa.example.internal"],
  "extensionId": "<реальный ID: 32 буквы a–p>",
  "updateUrl": "https://software.example.internal/tms/update.xml",
  "crxUrl": "https://software.example.internal/tms/studio.crx"
}
```

Это шаблон: значение ID нужно заменить, иначе сборщик намеренно завершится ошибкой.
Повторно собрать пакет в новый каталог, подписать тем же ключом. Для обновления
пакет и `update.xml` должны иметь одинаковую версию. Сервер обновлений доступен
браузерам без интерактивной авторизации, размещён внутри корпоративного контура;
права публикации выдаются только сопровождающим.

Сборщик создаёт `policy/ExtensionSettings.json` и альтернативную строку
`policy/ExtensionInstallForcelist.txt`. Администратор **добавляет запись этого ID**
к существующей политике, не заменяя правила остальных расширений. Для Edge это
Administrative Templates → Microsoft Edge → Extensions; GPO или профиль Intune
с соответствующими настройками. SCCM может доставить утверждённую политику
стандартным для организации способом. Сгенерированные файлы сами политику не применяют.
[Политики управления Edge](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-manage-extensions-policies).

Для установки вне магазина на Windows проверить условия управления устройством:
в частности, документация self-hosted Edge описывает доменные устройства Active Directory.
Совместимость с фактическим браузером, CSP TESSA и профилем управления проверяется
в пилоте. Локальная проверка Chromium не заменяет проверку конкретного Edge/Chrome
и доменных политик.

## Обновление, отключение и откат

1. Отключить старую копию userscript у участников пилота, чтобы не запускать две версии.
2. Проверить экспорт, Preview, безопасный отказ при недостаточных правах и тестовое
   применение на отдельной матрице с согласованным восстановлением.
3. Публиковать прошедший проверки CRX и затем обновлённый `update.xml`. Не менять
   содержимое уже опубликованной версии. Расширять группу установки после пилота.
4. Для отката выпустить сохранённый предыдущий код с **более высоким номером версии**,
   тем же ключом и ID. Снижение номера не является обычным автообновлением.
5. Для экстренной остановки администратор меняет централизованную политику установки/
   блокировки и просит закрыть открытые вкладки TESSA: уже внедрённый код не исчезает
   из страницы мгновенно. Перед закрытием не начинать новую запись и дождаться
   завершения/остановки текущей операции.

К заявке приложить исходный commit, сборку, SHA256, результаты тестов и
[отчёт по безопасности](SECURITY-REVIEW-2026-09-24.md). Назначить владельца ключа,
обновлений и регламент хранения диагностик. Сертификацию МОПО оформляет организация;
автотесты не являются заключением о сертификации.
