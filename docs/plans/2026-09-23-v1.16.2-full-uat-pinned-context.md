# v1.16.2 Full UAT pinned-context recovery

## Goal

Fix the live v1.16.1 Full UAT failure where the final recovery path reports "Во время UAT открыта другая матрица", then emits secondary Apply/Reconcile failures with 0 attempted writes and no DELETE receipt.

## Evidence

- Live UAT seed 2396555163: UNSAFE, PASS 1 / FAIL 3.
- final-restore-proof failed on active-matrix mismatch.
- action-apply had attempted=0/completed=0.
- action-reconcile had no DELETE receipt.
- v1.16.1 UI was loaded and ready in the saved TESSA page.
- Current Full UAT freshSnapshot() recreates TessaBridge from the *current UI context* every time, including finally/recovery.
- TESSA documentation warns that current-card context objects can change and recommends copying the current card/context value for later handlers.

## Root cause hypothesis to prove

The UAT recovery/read-back path is coupled to mutable active UI context. A context transition or ambiguous current-context lookup can make freshSnapshot() bind to a different matrix even when the UAT's original bridge is still the authoritative context. This blocks recovery before any live mutation, then action-coverage code incorrectly reports Apply/Reconcile as functional failures instead of not-run secondary evidence.

## Implementation

1. Add a regression contract that requires a pinned UAT bridge/context.
2. Capture the authoritative bridge + matrix/template identity once after initial validation.
3. Use the pinned bridge for read-back, cleanup and final baseline proof.
4. Keep an explicit active-context guard before destructive writes so real user navigation still fails closed before mutation.
5. Never use a newly discovered active matrix as the cleanup target.
6. If UAT aborts before any mutation:
   - final baseline proof uses the pinned context;
   - Apply/Reconcile are NOT_RUN, not FAIL;
   - no fake DELETE receipt is required.
7. If writes were attempted:
   - Apply evidence remains strict;
   - Reconcile still requires a real mutation receipt;
   - cleanup remains fail-closed and UNSAFE on unverified restoration.
8. Add fatalError to compact failure evidence so the primary failure is never hidden by secondary checks.
9. Bump exact live candidate to v1.16.2 and include the new transform/test in the GitHub Actions composition.

- Existing npm regression suite must remain green.
