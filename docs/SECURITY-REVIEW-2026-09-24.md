# Проверка безопасности: кандидат 1.16.15

Объект: исходный userscript, сборка через существующую цепочку hotfix,
Excel-парсер, справочники, диагностические экспорты, native CardService и
новый упаковщик корпоративного расширения. Проверка проведена по коду,
локальным предоставленным данным и тестам. Рабочие матрицы не изменялись.

## Подтверждённые находки и исправления

| Находка | Риск | Исправление и проверка |
|---|---|---|
| Raw-диагностика могла включать `Info.KrToken`, подписи и токены | Высокий: служебные данные могли попасть в передаваемый ZIP | Общая редакция чувствительных ключей, включая вложенные Map/typed fields, на границах JSON; исходные карточки не мутируются. `diagnostic-secret-redaction.mjs`, существующие diagnostic/support tests |
| Ключ кэша справочников не учитывал пользователя | Средний: повторное использование справочника другого сеанса на общем профиле | Origin + ID пользователя + шаблон + тип карточки + версия проекции. При неизвестном principal повторное использование кэша отключено. `scoped-catalogs-enterprise.mjs` |
| Виды документов не ограничивались типом карточки шаблона | Средний: неверный выбор и ошибочное назначение | `MtxRouteTemplate.CardTypeID` сопоставляется с `KrDocTypeCardTypeID`; свежая проверка новых назначений перед CardNew/Store. Отсутствие доступа, поля или полного справочника блокирует новое назначение |
| Справочник повторно сериализовал технические колонки в подробности/поиск | Лишний объём клиентских данных и работы | Проекция критериев сохраняет ID, название и поля уточнения; не размножает произвольный технический payload |

Редакция полей не означает обезличивание ZIP: диагностика содержит бизнес-данные,
названия, идентификаторы и иногда ФИО. Передавать её только в разрешённом контуре.
Произвольный секрет, вставленный в свободный текст, не обнаруживается гарантированно
по имени поля. Старые уже созданные ZIP новой редакцией не переписываются.

## Границы доступа и записи

Скрипт использует штатный API TESSA в сеансе пользователя, без сервисного аккаунта
или альтернативных учётных данных. Ошибка прав в CardGet/CardStore не превращается
в успешный результат и не вызывает повтор с ослабленными флагами. Отсутствующий
статус серверной валидации также считается ошибкой. В Store сохраняется проверка
версии карточки. Проверяются состояние матрицы, режим редактирования, принадлежность
строк, свежесть снимка и зависимости удаления. Тесты проверяют отказы и гонки.

Окончательная авторизация принадлежит **серверу TESSA**. Клиентский код пользователь
может изменить в DevTools; скрытие кнопки или экспортируемой функции не является ACL.
Поэтому на тестовом контуре обязательно проверить реальные серверные права для
просмотра, создания, изменения, удаления и чужой матрицы под разными ролями.
[OWASP: проверка разрешений на каждом запросе](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html).

Проверки типа документа в клиенте улучшают корректность Studio, но не заменяют
серверную бизнес-валидацию. Изменение типа шаблона между preflight и Store должно
отклоняться серверным расширением TESSA. Наличие такой серверной проверки здесь
не подтверждено и не может быть обеспечено userscript.

## XSS, Excel и распространение

`enterprise-security-boundaries.cjs` передаёт HTML/script/SVG/event-attribute
payload в заголовки, ID, названия и подробности реального picker. Проверяется,
что отображается текст и не создаются исполняемые узлы/атрибуты. Это адресные
регрессионные проверки, а не доказательство отсутствия любого XSS во всём TESSA.
Существующие тесты покрывают XML/ZIP, обход путей, пределы размеров, опасные
SpreadsheetML-конструкции и сохранение данных при roundtrip.

Корпоративный пакет использует статический локальный JavaScript, Manifest V3,
явные HTTPS-хосты, без `<all_urls>`, дополнительных API-разрешений и удалённых
исполняемых зависимостей. `MAIN` даёт доступ к API страницы и разделяет её доверенную
среду. Компрометация самой страницы/другого скрипта того же origin находится за
пределами защиты этого расширения. Ключ подписи и сервер обновлений контролирует ИТ.

## Проверки для допуска в промышленный контур

- Реальная ACL-матрица: запрещённые CardGet/CardNew/Store/Delete под ограниченными
  аккаунтами, проверка неизменности данных после отказа и штатного аудита TESSA.
- Реальные ограничения уникальности и типа документа, смена прав/шаблона во время
  операции; stale/version/lock-конфликты и восстановление после сетевого разрыва.
- Пилот подписанного CRX в корпоративном браузере с действующим CSP, GPO/Intune,
  обновлением, отключением и откатом.
- Согласование состава диагностик, сроков хранения, владельца ключа и публикации.

Не заявляется ни «полная безопасность», ни готовое заключение МОПО.
Пакет предоставляет воспроизводимые исправления и доказательства для проверки ИБ.
